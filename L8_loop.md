# L8 · Loop — the service

What every run leaves behind, what stops it, and what changes afterwards. Filled from A9. The runs themselves live in `../runs/`, one folder each.

Status: decided on 2026-10-29

## A9 · The kitchen ticket — decided on 2026-10-29

- The trace must show — steps · model tier · tools · MCPs · Skills · Hooks · sources · handoff receipts · checks · failed attempts · stop point · cost: One line per unit, no transcripts. Steps: unit, owner, start and end time, PASS/FAIL. Model tier: S1 = one strong model (name and version); harness = 'none – script vX'. Tools: S1 can only read its tray files and write reasons.json, memo_draft_<idea_id>.md and conviction_<idea_id>.json in the run folder. MCPs: hedge_funds, read-only, used by U1 and U8 only, with query count. Skills: thesis/memo template and shortlist template, name and version. Hooks: every script, name and version. Sources: tables used, snapshot ID, limit-policy version. Handoff receipts: pointer to the ticket's receipt rows. Checks: name and PASS/FAIL; on failure, which field failed. Failed attempts: count per idea and the check that failed, not the content. Stop point: unit and reason, or CLOSED. Cost: S1 tokens and cost per idea; scripts ≈ 0. For S1 the trace records input and output file names with a hash, model, tokens, attempts and which checks passed or failed, never its reasoning: the reasoning that matters is already in the memo (key risk, falsifier, exit level), where the PM can judge it.
- The 90-second audit — what happened? was it inside boundaries? what should change in the spec, Skill, Hook or eval?: What happened: ticket.md, first line — run status (CLOSED, or STOPPED + reason), then one row per idea. Inside boundaries: trace.md, first line, written by the harness — 'S1 DB calls: 0 · S1 files written: only reasons.json, memo_draft_<idea_id>.md and conviction_<idea_id>.json (per selected idea) · DB writes: 0 · receipts: all PASS · snapshot IDs consistent: yes · policy version: vX'; any value other than expected is a breach. What should change: evidence.md, in its 'Checks and results' and 'Stated uncertainty' sections — failed checks and repairs, WITHHELD inputs, Exceptions, and the PM's review minutes against the 10-minute KPI.
- Absolute tripwire — a deterministic boundary a Hook or script stops on, not the model: Any attempt by the workflow, harness or S1, to write to the database. A hook blocks it before it executes, the run is STOPPED instantly, no packet is released and the PM is alerted. The PM is the only one who changes records; a workflow that writes could approve its own trades, which is exactly the breach found in the data.
- Learning loop — every surviving instruction has one owner and one reason; deterministic requirements move out of prose into checks: Thesis format and templates are owned by the student as builder, and changes need PM approval. Harness scripts and checks are owned by the student, and every change needs a new fixture test first (A8). The limit policy is owned by the PM (it is data, not design). The ranking rule is decided by the PM and implemented by the student. Every surviving instruction carries one owner and one reason; an instruction without a reason is removed. A rule S1 keeps breaking in prose moves out of the prompt into a schema or a script check (e.g. if S1 keeps writing the exit level as text, U9's schema rejects anything that is not a number): prose → schema → script. v1 is frozen, so audit findings become v2 changes, never edits in place.

**Decision:** Every run leaves a one-line-per-unit trace headed by a harness-written boundaries line, a database write attempt is the one absolute tripwire, and every audit finding becomes a v2 change with one owner, moving rules from prose to schema to script.
